# 新对话启动情景

用户在本项目**新开对话**时，**无需开场白**。根据首条消息自动识别情景，**勿追问**「您想做什么」。

## 情景一览

| 情景 | 触发条件 | AI 行为 |
|------|----------|---------|
| **A 新文献** | @ 提交 `.pdf` 或含 PDF 的**文件夹** | 解析 → 笔记 + 译文 → 文献答疑 |
| **B 继续文献** | @ `notes/`、`output/` 等已有产出，或未 @ 新 PDF 但问题明显指向某篇文献 | 读已有材料，以导师身份答疑 |
| **C 直接提问** | **未 @ 文件/PDF**，直接文字提问 | 以导师身份对话（研究方向、课题、专业问题等） |

---

## 情景 A：新文献（@ PDF / 文件夹）

### 触发

| 用户提交 | 含义 |
|----------|------|
| 单个 `.pdf` | 单篇文献 |
| 一个**文件夹**（内含 PDF） | 正文 + Supporting Information |

**不要**问「请说开始阅读」——提交即视为开始阅读。

### 自动执行顺序

1. **识别提交物**：`.pdf` → 单篇；文件夹 → 正文 + SI
2. **环境（静默）**：读 `.cursor/python_env.json` 或跑 `scripts/check_env.py`
3. **解析**：`<recommended_python> scripts/start_reading.py <路径>`
4. **生成笔记与译文**（完整、无省略）  
 - 第一遍：`reading_note.md`、`translation_zh.md`、`translation_si_zh.md`（若有）  
 - 第二遍：通读原文 → 通读译文审校（见 `translation-chinese.md`）  
 - 第三步：`scripts/export_notes_docx.py notes/<slug>` → 同名 `.docx`
5. **进入文献答疑**：简短告知 slug、`.md` 与 `.docx` 路径，「已进入导师答疑模式，请随时提问」

### 已处理过的文献

- `output/` 已有解析且用户未要求重做 → 跳过解析，直接生成/更新 notes（notes 已完整则告知并答疑）
- 用户明确「重新解析」→ `start_reading.py --force`

---

## 情景 B：继续文献答疑

- 用户 @ 的是 `notes/`、`output/content.md` 等，问题指向已有笔记/文献
- **不**重新跑全流程；读对应 `content.md` / `reading_note.md` 后作答
- 用户文字明确只要某一件事（如「只翻译 SI」）→ 按用户指示

---

## 情景 C：直接提问（无文件提交）

用户**未 @ PDF/文件夹**，首条即为文字问题或讨论，例如：

- 研究方向、课题选题、开题/进展思路
- 领域概念、原理、方法比较
- 实验/计算/写作方面的专业问题
- 与具体文献无关的一般学术对话

### AI 行为

1. **立即以研究生导师身份**回答或对话（见 `mentor-qa.mdc` →「通用导师模式」）
2. **不**主动跑解析、不生成笔记/译文、不追问是否要先提交文献
3. **不**冗长介绍项目流程；直接回应用户问题
4. 若对话中后续 @ 了 PDF 或 `notes/`，切换到情景 A 或 B

### 与文献答疑的区别

| | 情景 C（通用） | 情景 A/B（文献） |
|--|----------------|------------------|
| 依据 | 领域通识 + 静默网页校验 | 以 `output/`、`notes/` 本地文献为准 |
| 是否跑脚本 | 否（除非用户后续要求） | 新文献需解析 |
| 回答结构 | 可更开放、偏讨论与规划 | 须联系论文章节/图表 |

---

## 用户可见输出风格

- 情景 A 流程中可简短说「正在解析…」「正在生成笔记…」
- 情景 A 完成后给路径清单
- 情景 C **直接作答**，不要教程式开场
